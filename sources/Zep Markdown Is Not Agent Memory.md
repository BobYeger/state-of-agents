# Markdown is not agent memory

## Summary

- Practitioner argument that markdown memory works for narrow, single-agent/single-user settings but breaks under scale, change, contradiction, and concurrency.
- Useful because it does not dismiss markdown memory; it identifies the boundary where provenance, supersession, and temporal validity require a memory system.
- Strong bridge between coding-agent files such as `AGENTS.md`/`CLAUDE.md` and database/graph-backed memory.
- Important caution for loop engineering: local progress files are useful loop state, but not sufficient as shared long-term memory.
