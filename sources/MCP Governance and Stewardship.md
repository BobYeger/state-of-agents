# MCP Governance and Stewardship

## Summary

- Governance formalized via SEP-932, announced in "Building to Last" (blog.modelcontextprotocol.io, July 31, 2025, by David Soria Parra); the docs page is the living canonical version.
- Hierarchy modeled on Python/PyTorch: Lead Maintainers (BDFL, final veto) > Core Maintainers (majority-vote veto, admin on all repos) > Maintainers (components/working groups) > Contributors; together the MCP Steering Group.
- All spec changes must go through Specification Enhancement Proposals (SEPs); Core Maintainers meet bi-weekly to review and vote; membership is individual, not company seats.
- Structure distinguishes Interest Groups (articulate problems) from Working Groups (produce SEPs and implementations), formalized by SEP-1302; SDK tiering defined by SEP-1730.
- Page now records MCP as "Model Context Protocol a Series of LF Projects, LLC" (post-December-2025 donation); current Lead Maintainers are David Soria Parra and Den Delimarsky, with 7 named Core Maintainers and Justin Spahr-Summers listed as Lead Maintainer Emeritus.
