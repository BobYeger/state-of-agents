# Harness Tracker

An agent harness is the execution scaffold around a model: prompt assembly, the agent loop, tool dispatch, context management, state and memory, sandboxing, permissions, streaming, event logs, compaction, subagents, skills, and resumability.

The practical question for every harness is how the loop closes: what the agent observes, where state lives, what can execute, when humans intervene, how memory and skills enter context, and what makes the run auditable or resumable.

## Schema

Each detailed profile receives one primary kind. A brand may appear in more than one row when it spans layers: for example, a coding harness and the control plane that dispatches it are different artifacts even when one vendor ships both.

| Field | Meaning |
|---|---|
| Name | Concrete artifact or pattern being tracked; split brands when their layers have different control boundaries. |
| Kind | One primary class: `harness-implementation`, `framework-sdk`, `managed-runtime`, `hosted-product`, `orchestrator-control-plane`, or `pattern`. Secondary capabilities stay in the descriptive fields. |
| Evidence level | Official architecture article, official docs, open-source code/docs, product-level only, or third-party/reverse-engineering. |
| Loop pattern | Plan-act-observe, tool loop, graph loop, leader-worker-verifier, plan/act modes, background async PR loop, etc. |
| State / context | Transcript, compaction, files, git history, durable session log, memory store, tree session, project artifacts. |
| Tools / runtime | Shell, filesystem, browser, MCP, code execution, sandbox, VM, GitHub Actions, Durable Objects, container. |
| Control layer | Approvals, permissions, path protection, sandbox, network policy, human-in-loop, PR review. |
| Multi-agent support | Subagents, handoffs, leader/worker/verifier, swarms, teams, none/extension-only. |
| Skills / memory | Agent Skills, AGENTS.md, project rules, long-term memory, procedural skill library. |
| Observability | Traces, logs, session replay, PR diffs, event stream, telemetry, checkpoints. |
| Primary sources | Official article/docs/repo links. |

## Profile Classes

| Primary kind | Inclusion boundary | Representative entries |
|---|---|---|
| `harness-implementation` | Owns and executes the model/tool loop in a concrete environment. | Codex, Claude Code, DeepSeek Harness, Grok Build, Pi, OpenHands, Cline, OpenCode, Goose, Qwen Code, Amp, Kiro |
| `framework-sdk` | Supplies components or an embedded runner from which developers build an executable agent. | OpenAI Agents SDK, Claude Agent SDK, LangGraph, Deep Agents, CrewAI, Google ADK, Microsoft Agent Framework |
| `managed-runtime` | Hosts agent code or configuration and owns sessions, isolation, scaling, or durable infrastructure; it need not own the inner loop. | Anthropic Managed Agents, Cloudflare Agents SDK / Project Think |
| `hosted-product` | Accepts a task through a provider-controlled harness and completes actions or returns a result, artifact, diff, or PR. | Cursor, Devin, Factory Droid, Grok Bot, Manus, GitHub Copilot coding agent, Google Antigravity |
| `orchestrator-control-plane` | Dispatches, coordinates, or governs other harnesses or task-scoped agents. | Buzz, GitHub Agent HQ, OpenAI Symphony, MiniMax Agent Team |
| `pattern` | Reusable loop pattern rather than one deployable product. | Ralph and self-improving harness loops |

The classes describe artifacts, not companies. OpenHands, for example, has an SDK, a default harness, and a remote Agent Server; this tracker profiles the default V1 harness while its source cards preserve the layer boundary. Framework ecosystems without a distinctive, well-evidenced mechanism remain in [[systems/agent frameworks and orchestration libraries]] rather than being promoted merely for catalog completeness.

## Harness Patterns

| Pattern | Examples | What to look for |
|---|---|---|
| Simple tool loop | OpenAI Agents SDK, Responses API | Model calls tool, observes output, repeats until done. |
| Coding-agent loop | Codex, Claude Code, Pi, OpenCode, Cline, Cascade | Read repo, plan, edit files, run shell/tests, observe, patch, summarize. |
| Plan/Act split | Cline, OpenCode, Windsurf Cascade | Read-only planning separated from write/execute mode. |
| Deliberative control | Three-layer architectures, plan-then-execute, planner-executor-verifier | Planning, execution, observation, and verification have explicit boundaries and authority. |
| Durable session + sandbox | Anthropic Managed Agents, Cloudflare Agents, Manus, Jules, Copilot cloud agent | Long-task state persists outside model context; execution happens in an isolated environment. |
| Durable dormant agent | Google ADK durable agents | Agent pauses on external blockers, persists explicit state, and wakes on events. |
| Initializer + worker handoff | Anthropic long-running harness | First agent creates artifacts; later agents resume from them. |
| Workflow pattern selection | Claude common workflow patterns, Anthropic building effective agents eBook, Anthropic building effective agents | Match the harness flow to the task: sequential for dependencies, parallel for independent work, evaluator-optimizer for measurable quality gaps. |
| Hook-based control | Claude Code hooks, Cline lifecycle hooks, Kiro hooks, OpenHarness middleware, CrewAI hooks, Cloudflare Think lifecycle hooks | Intercept lifecycle events to inject context, gate tools, run validators, block stopping, log telemetry, or integrate external systems. |
| Ralph loop | Ralph Playbook, Claude Code-style coding agents | Repeat short fresh-context coding loops over specs, plans, tests, commits, and repository state. |
| Loop engineering | Codex Goals, Claude Code `/loop`, Claude Code workflows, GitHub Agentic Workflows, Ralph loop, Addy/Andrew/Armin June 2026 practitioner sources | Design the outer recurrence: wake trigger, objective, durable state, verification, retry, stop policy, cost/permission bounds, and human feedback cadence. |
| Code/software factory | Factory 2.0, Microsoft agent factory, OpenAI Symphony, Codex/Claude automations | Treat the SDLC as an instrumented control plane: signals -> triage/spec -> agent workspaces -> verification/review/release -> monitoring -> next signals. |
| Workflow-script orchestration | Claude Code Workflows, Recursive Agent Harnesses, GitHub Agentic Workflows | Put the plan and intermediate coordination state in executable workflow code rather than only in the lead agent's context. |
| Self-improving code loop | Autoresearch, Darwin Godel Machine, Meta-Harness, AlphaEvolve, Self-Harness, HarnessFix | Mutate executable code/procedures, evaluate externally, archive or select variants, and rollback failures. |
| Planner/generator/evaluator | Anthropic app-development harness | Generation and evaluation are separate agents and context resets are explicit. |
| Outcomes / rubric grader | Claude Managed Agents, Anthropic app-development harness | A separate evaluator scores output against a rubric and sends repair feedback. |
| Leader/Worker/Verifier | MiniMax Agent Team | Leader decomposes; workers execute; verifiers challenge and force revisions. |
| Memory-first agent | Letta, Hermes | Agent persists identity, preferences, lessons, and self-edits memory. |
| Dreaming / memory consolidation | Claude Managed Agents, Letta | Background reflection extracts patterns from prior sessions into future memory. |
| Extensible minimal core | Pi, OpenClaw, OpenHarness | Keep core small; add tools, skills, subagents, policies, and UI through extensions. |
| Fully plugin-composed harness | DeepSeek Harness / Cordis | Make the loop, model adapters, session log, tools, compaction, subagents, and workflows scoped plugins with reversible lifecycle effects; verify that each plugin preserves the framework's composition preconditions. |
| Progressive operating surface | Code Mode, Codex CLI as MCP, Cloudflare CLI | Large API/tool surfaces are exposed through code, CLI, search, or SDK wrappers instead of dumping every schema into context. |
| Client/server harness | OpenCode, Cline Hub, Amp runners | Keep the loop behind a local or remote service so terminal, editor, web, SDK, automation, and orchestration clients share one session model. |
| Spec-artifact lifecycle | Kiro CLI v3 (Early Access) | Persist requirements, design, and dependency-aware tasks as the control plan against which execution is verified. |
| Worktree isolation | Claude Code, Codex app, Cursor | Give each coding-agent task a separate checkout so parallel edits and review state do not collide. |
| Issue-tracker control plane | OpenAI Symphony | Tickets become durable work units and isolated agent workspaces. |
| PR-producing async agent | Devin, Copilot cloud agent, Jules, Codex Cloud | Agent works in background and produces branch/diff/PR for review. |
